# 敵対的検証の方法論 — 候補を殺す技術

未在工学の成否は生成ではなく検証で決まる。LLM は候補を無限に生成できる。
価値があるのは**殺しにかかっても死ななかった候補**だけである。本書はその殺し方を定める。

## 1. 検証の哲学: 生成者は検証者になれない

同一の思考の流れの中で生成と検証を行うと、検証は必ず甘くなる。生成した瞬間、その案には「自分の案」という重みがつき、以降の探索は無意識に生かす証拠へ偏る(確証バイアス)。LLM はこの偏りを人間以上に強く示す——もっともらしい擁護論を流暢に無限生成できるからである。

対策は**構造的な役割分離**である:

- 走査フェーズ(Phase 2)では検証を禁止する。「これは既にありそう」という内なる声も無視して記録する(その判断は誤りやすく、発散を殺す)
- 検証フェーズ(Phase 4)ではペルソナを明示的に切り替える: 「私はこの案を殺すことが仕事の審査官である」。この宣言は儀式ではない——LLM の出力分布は役割の記述で実際に変わる
- 検証の合格基準は「良さそうに見える」ではなく「殺す試みが列挙され、すべて失敗した」である

## 2. 三重ゲート選別(Phase 3)

敵対的検証(Phase 4)は高価である(候補1件あたり検索6本以上)。その前に安価なゲートで数を絞る。

### ゲート1: 部品実在性

LLM は実在しない部品を平気で組む。「高精度な非侵襲血糖センサー」「安価な室温量子センサー」——語として自然なら、実在しなくても設計に使ってしまう。全構成要素について WebSearch で実在を確認し、URL を付ける。付けられない部品は「仮定」ラベル。**仮定部品が過半の原石は落選**。仮定部品を含んだまま生き残った候補は、カードの部品表にラベルを残す(読者への誠実性)。

### ゲート2: フェルミ検算

エネルギー収支・単価・市場規模のうち候補に関係する量を、桁の精度で1行計算する。目的は精密さではなく**桁で破綻している案の即時棄却**である(例: 電池容量が物理的に3桁足りないウェアラブル、受益者数×支払意思額が開発費を2桁下回る市場)。計算の実物をカードに残す——「計算した」という主張ではなく計算そのものを。

### ゲート3: 価値仮説

「誰の・どの苦痛が・何桁改善するか」を一文で言えない原石は落選。このゲートはグッドハート対策である: 未在性(まだ無いこと)を最適化目標にすると、奇抜だが無価値な案が量産される。**まだ無くて、かつ、あれば桁で効く**——両方を要求する。

## 3. 存在検索の設計(Phase 4a)

### 名前で探さない

未発見候補の多くは C 類型的性質を持つ——**名前がない**。名前で検索して0件でも何の情報もない。機能語(固有名詞を消した「何を何にする」)で探す。クエリ変形規則と系統(機能+制約/実務者語彙/否定形・嘆き形/特許)は `search-playbook.md` に定める。

### ログが本体

新規性判定の実体は判定語(暫定新規/差分新規/既存)ではなく、**その判定に至った検索クエリの全記録**である。ログのない判定は無効。後日、同じ候補を再走査する者は、ログとの差分だけを検索すればよい——検索ログは未在工学の再利用可能な資産である。

## 4. 墓場検索 — 失敗の考古学(Phase 4b)

「誰も試していない」は弱い証拠である(見つけられていないだけかもしれない)。「**試されて死んだ、そして死因が消えた**」は強い証拠である——需要の実在と部分的な技術成立性が、他人の資本で実証済みだからである。

手順:
1. 候補の機能語+「撤退|failed|discontinued|post-mortem」で死骸を探す
2. 死骸が見つかったら死因を一文で特定する: [技術不足|コスト|規制|時期尚早|需要不在]
3. 死因が現在のイネーブラで解消されているかを判定する
   - **解消の証拠あり**(コスト曲線・新素材・新規制のURL)→ 候補は生存し、D類型として強化される
   - **解消の証拠なし** → 棄却。死骸URLと死因を棄却ログへ
   - **死因が「需要不在」の場合は特に慎重に**: 需要不在は時代で変わりにくい。「当時は需要がなかったが今はある」と主張するには、需要側の変化の出典が必要

## 5. 説明責任テストと残余Xトラック(Phase 4c)

生き残った候補に最後の問いを課す: **「これほど良い案が、なぜまだ無いのか。」**

答えは未在類型(A〜H)で与えられなければならない。「たまたま」「誰も思いつかなかった」は答えではない——世界には思いつく人間が常に大量にいる。良い案が未在であるには構造的理由が要る。

ただし、この テストには既知の穴が2つある:

- **穴1: LLM は合理化の名手**。もっともらしい「未発見理由」は無限に生成できる。だから説明の順序を固定する: **まず存在検索・墓場検索(4a/4b)で「実は在る」を潰し、その後で初めて「なぜ無いか」を語る**。証拠より先に物語を作らせない
- **穴2: 逆棄却の危険**。本当に新しいものほど既存類型に収まらない可能性がある。だから説明できない候補は**棄却しない**。残余Xトラックに隔離し、カード化はするが確信度「不明(残余X)」とし、人間のレビューに委ねる。X 事例の蓄積は分類学改訂の入力になる(docs/05)

## 6. 新規性判定の言語規約

| 判定語 | 定義 | カード化 |
|---|---|---|
| **暫定新規** | n クエリ(ログ付き)で反例なし | する |
| **差分新規** | 近い先行例があるが明確な差分がある(差分を明記) | する |
| **既存** | 先行例と実質同一 | しない(棄却ログへ) |

禁止表現: 「新規と確認した」「存在しないことを確認した」「特許性がある」。
必須免責(最終報告に定型で含める): 「本結果はスクリーニングであり、特許侵害調査(FTO)でも網羅的な先行研究調査でもない。新規性判定はすべて走査日時点の暫定判定である。」

この規約は謙遜ではなく精度である。Web検索で到達できるのは公開情報の一部にすぎず、判定は原理的に可謬である。可謬性を明記した判定だけが再走査に耐える。

## 7. LLM 幻覚の既知パターンと対策

| パターン | 症状 | 対策 |
|---|---|---|
| 実在しない部品 | 語として自然な架空デバイス・素材を設計に組み込む | ゲート1(部品実在性)。URL 無き部品は「仮定」ラベル |
| 出典なき趨勢主張 | 「〜のコストは急落している」「〜が普及しつつある」 | 出典URL必須。裏取り不能なら「仮定」に格下げ(削除ではなく——仮定の明示は情報である) |
| 「思いついた」錯覚 | 訓練データに在るものを新規と感じる | 新規性欄は検索ログ付きでのみ記入可(スキルで強制) |
| 合理化 | どんな案にも、もっともらしい未発見理由を後付けする | 4a/4b(証拠)を4c(説明)より先に実行する順序固定 |
| 平均回帰 | どの領域でも似た候補(アプリ・プラットフォーム・AI活用)に収束する | 強制離心(乱択ペアリング・時代シフト・制約反転)の必須化 |
| 架空URL | 実在しない出典URLを生成する | URL は WebSearch / WebFetch の結果からのみ転記する。記憶からのURL記入を禁止 |

## 8. 反証可能性テスト(Phase 4d)

各カードに「死亡条件」(この案を最速で殺す反証)と「最小実験」(48時間・低予算の検証手順)を要求する。

48時間で設計できない候補は棄却しないが「検証不能」フラグを付ける。このテストの目的は2つ:
1. カードの受け手が**翌日から動ける**こと(検証不能な壮大な構想は、正しくても行動を生まない)
2. 死亡条件を書けない案は、実は主張内容が空である可能性が高い(反証可能性は主張の実在性のリトマス紙)
