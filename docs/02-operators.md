# 検出オペレータ集 — 類型を候補に変換する手続き

未在類型(docs/01-taxonomy.md)は診断の語彙であり、それ自体は何も生成しない。
本書は各類型を**実行可能な手続き**に変換する。オペレータは対で設計される:

- **発掘オペレータ**: 対象領域から、その類型が発火している痕跡(素材)を掘り出す
- **変換オペレータ**: 発掘した素材を発明候補の「原石」(1行仕様)に変換する

すべてのオペレータは LLM エージェントが実行することを前提に、入力・手順・出力・失敗モードを定義する。プロンプト雛形は `.claude/skills/mizai/references/operators-prompts.md` にある。

## 使い方の原則

1. **発掘と変換を分離せよ**。発掘の途中で候補を思いつくと、発掘が止まる(最初の光る石で満足する——それ自体が類型H)
2. **原石の段階では裏取りしない**。走査フェーズは発散専用。検証は別フェーズ・別ペルソナで行う(docs/03)
3. **量を決めてから掘る**。「候補が出たら次へ」ではなく「各類型で最低3件」と先に決める。空振りした類型は空振りと記録する(それ自体が領域の情報である)

---

## A: 前提発掘 → 反転

**発掘(前提発掘)**
- 入力: 領域プロファイル(Phase 1 の地図)
- 手順: 以下の3経路で暗黙前提を10件以上列挙する
  1. 教科書経路: 「この分野の入門書の第1章に証明抜きで書かれることは何か」
  2. 定義経路: 領域の中心語の定義を書き下し、定義に密輸されている前提を摘出する(例: 「ゲームとは画面と操作で——」の「画面」「操作」)
  3. 嘲笑経路: 「この分野で口にすると素人扱いされる質問は何か」
- 出力: 前提リスト(各項目に「経験則/法則/慣習」のラベル)
- 失敗モード: 物理法則を前提リストに混ぜる。ラベル付けで防ぐ

**変換(反転)**
- 手順: 「経験則」「慣習」ラベルの前提それぞれについて「この前提が偽である世界で成立する製品・手法」を記述する。前提が*かつて真だったが条件が変わった*ものを優先する
- 出力: 原石(1行仕様+発火類型A)

## B: 断絶地図 → 構造移植

**発掘(断絶地図)**
- 入力: 領域の未解決問題リスト、隣接分野リスト
- 手順: 領域の各未解決問題を**機能語**(固有名詞を消した抽象記述)に変換し、「この機能課題を日常的に解いている別分野はどこか」を問う。学会・業界誌・求人の重なりが無い分野ペアを優先する(交流が無いことが B の条件)
- 出力: (問題, 解を持つ可能性のある異分野)のペアリスト
- 失敗モード: 既に交流が盛んな分野ペア(例: 機械学習×創薬)を挙げる。それは B ではなく E か、単なる既存潮流

**変換(構造移植)**
- 手順: 異分野の解法の**構造**(何を何に変換しているか)を抽出し、固有名詞を対象領域の要素で置換して移植する
- 出力: 原石(1行仕様+発火類型B+移植元)

## C: ワークアラウンド考古学 → カテゴリ化

**発掘(ワークアラウンド考古学)**
- 入力: WebSearch(フォーラム、レビュー、SNS、Q&Aサイト)
- 手順: 領域の実務者・当事者が「仕方なく」続けている応急処置を発掘する。検索語: 「仕方なく」「とりあえず」「自分はこうしてる」「workaround」「hack」「頑張って手作業」。Excel・付箋・LINEグループ・タイマーの転用例は宝脈
- 出力: ワークアラウンド一覧(各項目に出典URL——このフェーズで唯一、出典を要求する発掘オペレータ。応急処置の実在が候補の需要根拠になるため)
- 失敗モード: 既に製品カテゴリが存在する不満(単なる改善要望)を拾う。「専用品が存在しないので転用している」ものだけを拾う

**変換(カテゴリ化)**
- 手順: 各ワークアラウンドについて「この応急処置が専用の製品カテゴリだったら、それは何と呼ばれ、何をするか」を記述する
- 出力: 原石(1行仕様+発火類型C+元ワークアラウンドのURL)

**変種(記法の欠如)**: 「この分野で皆が散文・口伝で説明し続けているものは何か。記法(図式・型・言語)を与えたら何が建つか」。出力は記法そのものを発明候補とする

## D: 墓場発掘 → 死因照合

**発掘(墓場発掘)**
- 入力: WebSearch
- 手順: 領域で「試されたが死んだ」案を発掘する。検索語: 「実用化されなかった」「撤退」「failed」「abandoned」「discontinued」「なぜ普及しなかった」。放棄特許・撤退スタートアップ・終了した国家プロジェクトを含む。各案について**死因を一文で**特定する(技術不足/コスト/規制/時期尚早/需要不在)
- 出力: 棚上げ案一覧(案, 死亡年代, 死因, 出典URL)
- 失敗モード: 死因の特定を省いて「昔あった面白い話」の収集になる。死因の無い項目は変換に進めない

**変換(死因照合)**
- 手順: Phase 1 で列挙した現在のイネーブラ(コスト曲線・新素材・新規制・LLM等)と死因を突き合わせ、「死因が解消された棚上げ案」だけを原石化する。復活の形は原案のままとは限らない——死因を回避する再設計を許す
- 出力: 原石(1行仕様+発火類型D+死因と解消イネーブラの対)

## E: 掃引表 → 非自明セル展開

**発掘(掃引表)**
- 入力: 領域の機能要素リスト(縦軸)、異分野の構造・技術リスト(横軸)
- 手順: 掃引表(形態分析表の変種)を作る。横軸には Phase 1 の隣接分野に加え、**乱択で選んだ無関係分野を最低2つ**含める(強制離心、後述)。各セルを「自明(既存)/不毛(物理・経済的に無意味)/非自明」に3値分類する。分類は高速に、1セル1行で
- 出力: 分類済み掃引表
- 失敗モード: 全セルを丁寧に検討して時間切れになる(E類型の再演)。3値分類はふるいであって分析ではない

**変換(非自明セル展開)**
- 手順: 「非自明」セルのみ、組合せの具体的な形を記述する
- 出力: 原石(1行仕様+発火類型E+セル座標)

## F: 誘因地形図 → 谷底さらい

**発掘(誘因地形図)**
- 入力: 領域プロファイル
- 手順: 領域内の問題群を「解いたら誰が儲かるか/評価されるか」で塗り分ける。誘因の谷を列挙する: 学会が無い、論文にならない、VCが来ない、受益者に購買力が無い、タブーに触れる、担い手の地位が低い
- 出力: 誘因の谷リスト(谷ごとに、誘因が無い構造的理由)
- 失敗モード: 「儲からない=価値が無い」と混同する。F類型の谷底には価値と誘因が乖離した案が沈んでいる

**変換(谷底さらい)**
- 手順: 各谷について「技術的には容易だが誘因不在で未着手の案」を記述する。あわせて「誘因の地形を変えるイネーブラ(制度変更・オープンソース・AI開発コスト低下)が到来していないか」を問う——到来していれば候補は浮上可能
- 出力: 原石(1行仕様+発火類型F+誘因欠如の理由)

## G: 不可測量リスト → 計測器変換

**発掘(不可測量リスト)**
- 入力: 領域プロファイル、実務者の語彙
- 手順: 実務者が言語化するが数値化できていない量を列挙する。信号語: 「経験と勘」「様子を見る」「手の感覚」「嫌な予感」「熟練者にしか分からない」。各項目に「原理的に計測不能/未計測」のラベルを付ける
- 出力: 不可測量リスト
- 失敗モード: 既に計測器が存在する量(単に普及していないだけ)を挙げる。それはむしろF類型かH類型

**変換(計測器変換)**
- 手順: 「未計測」ラベルの各量について、二階建てで候補化する
  1. 一階: その量を計測する装置・手法そのもの
  2. 二階: 計測できたと仮定して、その上に建つ発明(G類型は解錠型——一階より二階の方が大きいことが多い)
- 出力: 原石(1行仕様+発火類型G+一階/二階の別)

## H: 性能天井の明示化 → 桁違い仮定

**発掘(性能天井の明示化)**
- 入力: 領域の支配的な解のリスト
- 手順: 各支配解について「現行性能/理論限界」の比を桁で見積もる。理論限界は物理限界・情報理論限界・経済的下限のいずれでもよい。粗くてよいが、必ず数字にする
- 出力: (支配解, 現行性能, 理論限界, 比)の表
- 失敗モード: 理論限界の見積もりを避けて「もっと良くなるはず」で済ませる。数字にしない項目は変換に進めない

**変換(桁違い仮定)**
- 手順: 比が2桁以上開いている支配解について「桁違いの解が存在すると強制仮定せよ。それはどんな形か。なぜ誰も比較しなかったのか」を記述する
- 出力: 原石(1行仕様+発火類型H+性能比)

## 横断オペレータ: 強制離心

LLM は訓練分布の平均に回帰する。放置すると、どの領域を走査しても似た候補(アプリ、プラットフォーム、AI活用)が出る。以下を**必須**とする:

1. **乱択ペアリング**: 対象領域と無関係な分野を乱数的に1つ選び(手順: 思いついた分野の候補を10個列挙し、走査開始時刻の分の1桁で選ぶ等、恣意を排す方法なら何でもよい)、B・E のオペレータを追加適用する
2. **時代シフト**: 「この領域の問題を1950年の技術だけで/2050年の技術水準で解くとしたら」を各1回問う。現在の道具立てへの固着を外す
3. **制約反転**: 領域の代表的制約(予算・人手・時間)を1つ選び「この制約が10倍厳しい/10倍緩い世界の解」を問う

強制離心の出力も通常の原石として記録する(発火類型は B または E)。

## オペレータの選択と併用

- **全類型掃引(標準モード)**: A→H の順にすべて適用。順序に意味がある——A(前提)を最初に外しておくと、以降のオペレータが檻の外で動く
- **指定類型モード(高速)**: Phase 0 で領域の特性から発火しやすい類型を2〜3個選んで適用。選定の目安は領域の年齢(古い領域はH・A、若い領域はE・G)、担い手の地位(低いならF・C)、技術変化の速度(速いならD)
- 1つの原石に複数類型が発火した場合は主類型1つを選ぶ(判別フローチャートは docs/01 §10)
