# 自己適用と改良ループ — フレームワークが自分を走査する

「未発見の大発明を発見するフレームワーク自体が、未発見の発明であってほしい」という要求に対する本体系の答えは、自称ではなく**自己記述可能性**である。すなわち: 本フレームワークを自分自身のスキーマ(発明候補カード)で記述し、自分自身の検証手続き(敵対的検証)にかけ、自分自身の改訂機構(残余Xトラック)で更新し続けられること。

## 1. 自己適用の手順

対象領域を「発明方法論」に設定して mizai スキルを走らせるだけである。特別な手順は要らない——それが自己適用可能性の意味である。

- Phase 1 の地図化は「発明方法論の支配的アプローチ(ブレスト、TRIZ、デザイン思考…)、イネーブラ(LLM)、実務者のワークアラウンド(付箋とホワイトボード)、棚上げ案(効果検証で死んだ手法群)」を測量する
- Phase 2 の走査では、たとえば類型Hが「ブレインストーミングは効果への反証研究が蓄積してもなお支配的(満足化の影)」を検出し、類型Bが「発明方法論の研究(認知科学・経営学)と発明の実務(エンジニアリング)の断絶」を検出する
- この走査から得られた候補の一つが、未在工学自身である(§3)

## 2. 残余Xからの類型改訂プロトコル

走査のたびに Phase 6(帰還)が以下を蓄積する: 類型別ヒット率/棄却理由の分布/残余X事例。

改訂は次の規則で駆動する:

1. **X 事例が3件を超えて共通パターンを示したら**、新類型を起案する。起案には (a) パターンの定義 (b) 歴史事例2件以上 (c) 判別質問 (d) 発掘・変換オペレータの対、の4点セットを要求する(既存類型と同じ装備を持たない類型は追加しない——類型のインフレは分類学を殺す)
2. **ある類型のヒット率が継続的にゼロなら**、その類型の統合・削除を検討する(格子は有用性で維持される。docs/01 §12)
3. 改訂は docs/01 のバージョンを上げ、改訂履歴に「駆動した X 事例」を記録する。カードの「メタ」欄が taxonomy のバージョンを持つのはこのためである——古いバージョンで走査されたカードは、新バージョンで再診断できる

このループが意味するのは: **未在工学の分類学は主張ではなく計測装置であり、較正され続ける**ということである。

## 3. フレームワーク自身の発明候補カード

本フレームワークを、本フレームワークのスキーマで記述する。

```markdown
# 発明候補カード SELF-01: 未在工学(Absence Engineering)

- **仮称**: 未在工学
- **一行仕様**: 発明を志す個人・組織・AIエージェントのために、「大発明が未発見のまま残存する構造的理由」を、分類学(未在類型A〜H+X)と類型別検出オペレータと敵対的検証で系統的に走査可能にする方法・体系
- **未在診断**: 主類型B(領域の断絶)、副類型C(名前なき需要)。
  発明の「方法」を研究する分野(認知科学・経営学・TRIZ実務)と、発明の残存理由を断片的に扱う諸分野(科学史、投資デューデリジェンス、未発見公共知識研究)は、互いをほぼ引用しない。
  また「未発見理由の分類」という方法需要には名前が無く、誰もそれを製品カテゴリとして探さなかった。
- **イネーブラ**: LLM エージェント。類型別オペレータの実行(前提列挙・機能語変換・掃引表・検索ログ付き検証)は人手では高コストで、方法論として書かれても実行されなかった(それ自体が類型D的死因)。エージェントが手順書を直接実行できる環境の到来が死因を解消した
- **部品表**: 歴史事例からの類型帰納[実在確認済み(docs/01 に事例記載)]/検出オペレータ[実在確認済み(docs/02)]/敵対的検証手続き[実在確認済み(docs/03)]/LLM エージェント実行系[実在確認済み(.claude/skills/mizai)]
- **価値仮説**: 発明・研究開発・新規事業の従事者/「何を探せばいいか分からない」という探索の初期コスト/アイデア出しの歩留まり(有望候補到達までの試行数)を1桁改善する——という仮説。未検証
- **フェルミ検算**: 人手の類型走査(1領域8類型×発掘・変換)≈ 数人日。エージェント実行 ≈ 1〜2時間+検索数十回。実行コストは約1桁強の削減
- **新規性ログ**: docs/04 §2 に差分論証。近接先行例: TRIZ(解法パターンの分類——ただし対象は解法であって残存理由ではない)、Swanson の未発見公共知識(類型Bの学術版——ただし文献結合に限定)、ジョブ理論(類型Cの市場版——ただし市場に限定)。判定 = **差分新規**(「断片は各所に在り、実行可能な統合体系が無かった」という主張の範囲で)
- **死亡条件**: (1) 実走査の歩留まりが、同じ工数の自由なブレインストーミングと有意に変わらないことが反復して観察される (2) 生成されたカードの「暫定新規」判定の大半が、専門家レビューで既存と判明する
- **最小実験**: 1領域を選び、mizai 走査と同工数のフリーブレストを並走させ、生成候補を第三者(候補の出自を伏せる)に新規性・価値で盲検評価させる
- **先行指標**: LLM エージェントの検索・検証コストの低下/特許・論文全文検索APIの開放/「negative results」出版の制度化
- **確信度**: 中(体系は動くが、歩留まりの優位は未検証)
- **メタ**: 2026-07-03/taxonomy 1.0/自己適用
```

このカードの要点は「差分新規」という判定と「死亡条件」の明記にある。本フレームワークは自身を大発明と主張しない。**自身が無価値だと判明する条件を書ける程度に、主張内容が具体的である**——それが「フレームワーク自体が発明であってほしい」という要求への、知的に誠実な最大回答である。

## 4. 改訂履歴の運用

- 本体系のバージョンは docs/01(分類学)のバージョンで代表する。現行: **taxonomy 1.0(2026-07)**
- 改訂の単位: 類型の追加・統合・削除、判別規則の変更、オペレータの追加。文言修正はバージョンを上げない
- すべての実走査(examples/ 配下)はメタ欄にバージョンを刻む。バージョン改訂時、過去カードの再診断は義務ではないが、X トラックのカードは優先的に再診断する(新類型はたいてい X から生まれるため、再診断で確信度が変わる可能性が最も高い)
