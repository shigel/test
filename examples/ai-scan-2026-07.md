# 発明候補カード MZ-AI-01: 不確かさ配管

- **仮称**: 不確かさ配管(Uncertainty Plumbing)
- **一行仕様**: LLMアプリの運用・障害調査者のために、パイプライン各段(検索・ツール・生成)の不確実性推定値を、OpenTelemetry スパンの標準属性として記録し下流へ伝播・合成する記法と参照実装
- **未在診断**: 主類型B(領域の断絶)、副類型A(前提「評価はリリース前工程」)。UQ は NLP 研究界隈の題材、トレーシングは SRE 界隈の道具で、学会・求人が重ならない。「スパンに不確実性を流す」方向を誰も見ていない。
- **イネーブラ**: UQ手法の成熟 https://arxiv.org/abs/2510.12040 / OTel GenAI semconv の標準化 https://opentelemetry.io/blog/2026/genai-observability/ / 推論費下落でサンプリング型UQが実用域 https://epoch.ai/data-insights/llm-inference-price-trends
- **部品表**: UQ推定器(semantic entropy 等)[実在確認済み https://arxiv.org/abs/2510.12040]/OTel GenAI スパン規約[実在確認済み https://mlflow.org/docs/latest/genai/tracing/opentelemetry/genai-semconv/]/トレース基盤のスコア添付機構[実在確認済み https://langfuse.com/docs/observability/overview]/段間の不確実性合成規則[仮定—学術提案のみ https://arxiv.org/html/2604.23505v1]
- **価値仮説**: 障害調査者の「どの段が信用できないか」特定時間を1桁削減。低確信の中間結果が高確信の最終出力に化ける「伝播失敗」を実行時遮断
- **フェルミ検算**: サンプリング型UQ(N=5、1k tokens、$0.4/M)≈ $0.002/リクエスト。調査1件のエンジニア1時間($100)=5万リクエスト分の計装費 → 2桁下で回収
- **新規性ログ**: 上記 §5 K1 の Q1〜Q6(全列挙)。最接近先行例 arXiv:2604.23505、差分=標準化・実装の未在。判定=**差分新規**
- **死亡条件**: (1) 較正不良で「確信度の高い幻覚」が支配的と実証される (2) OTel GenAI SIG が不確実性属性を採択済みと判明
- **最小実験**: 48時間。失敗原因特定済みの RAG トレース50件に semantic entropy をスパン伝播で後付けし、「最低信頼スパン=失敗原因段」一致率をランダム基準と比較。有意差なしなら棄却
- **先行指標**: OTel GenAI SIG の uncertainty 属性 issue/主要 API の不確実性出力拡充/可観測性ツールの uncertainty 機能発表/arXiv:2604.23505 系の参照実装公開
- **確信度**: 中(部品3/4実在。合成規則が仮定部品、較正リスク残)
- **メタ**: 走査日 2026-07-03 / taxonomy 1.0 / 全類型掃引(標準)

# 発明候補カード MZ-AI-02: 節穴検出器

- **仮称**: 節穴検出器(評価系の変異原性試験)
- **一行仕様**: LLMアプリの評価担当者のために、既知欠陥を注入したモデル変異体群を用いて、評価パイプライン全体(データセット+LLM-as-judge+ルーブリック)の欠陥検出力を測定する方法
- **未在診断**: 主類型B(領域の断絶)、副類型D(実現手段の遅延)。mutation testing はソフトウェアテスト界隈の30年物の道具だが LLM 評価界隈と担い手が重ならず、「評価系の側を試験する」方向が未踏。変異体ごとの再実行コストという死因も推論費下落で解消したばかり。
- **イネーブラ**: 推論費年10倍下落 https://epoch.ai/data-insights/llm-inference-price-trends / eval 基盤の普及 https://langfuse.com/docs/evaluation/overview / モデルレベル変異注入の先行技法 https://arxiv.org/abs/1805.05206
- **部品表**: 欠陥注入手段(プロンプト毒入れ・過量子化・LoRA劣化)[実在確認済み https://arxiv.org/abs/1805.05206]/eval ハーネス[実在確認済み https://langfuse.com/docs/evaluation/overview]/mutation score 定義[実在確認済み https://arxiv.org/html/2506.02954v2]/LLM固有欠陥カタログ(幻覚率増・指示無視・形式崩れ・迎合)[仮定—体系化された公開カタログ未確認]
- **価値仮説**: 「eval が緑のまま劣化がすり抜ける」見逃しリリース事故の予防。評価系の盲点特定を本番事故からの逆算(数週間)から事前監査(数時間)へ2桁短縮
- **フェルミ検算**: 変異体20体×eval 1回 $1〜10=$20〜200/監査。silent regression 1件の事故対応(数十時間×$100=数千$)より1〜2桁安い
- **新規性ログ**: 上記 §5 K6 の Q1〜Q7+墓場(全列挙)。最接近先行例 DeepMutation、差分=評価系全体への適用と LLM 欠陥カタログの未在。判定=**差分新規**
- **死亡条件**: (1) 注入欠陥が実運用の劣化様態を代表せず検出力スコアが本番見逃し率と無相関と実証 (2) eval ベンダーの既製「eval QA」機能に実質同一物を発見
- **最小実験**: 48時間。劣化変異体10体(毒入れ・過量子化・指示追従除去)で手元評価セットの検出率を測定。既存 eval が全変異体を難なく検出するなら価値仮説を棄却
