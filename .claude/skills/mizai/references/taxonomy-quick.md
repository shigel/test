# 未在類型 早見表(実行時参照用)

完全版: docs/01-taxonomy.md(バージョン 1.0)

| 類型 | 名称 | 軸 | 一行定義 | 検出の信号 |
|---|---|---|---|---|
| A | 前提の檻 | 認知 | 共有された偽の前提が着想を遮る | 教科書第1章の無証明の断言、「素人扱いされる質問」 |
| B | 領域の断絶 | 構造 | 部品が別分野に分散し、両方を知る者がいない | 学会・業界誌・求人が重ならない分野ペア |
| C | 名前なき需要 | 動機 | 需要に名前がなく、誰も「問題」と認識しない | 実務者の応急処置・転用(Excel、付箋、タイマー) |
| D | 実現手段の遅延 | 手段 | 過去に試され手段不足で死んだ案の死因が消えた | 「実用化されなかった」「撤退」+新イネーブラ |
| E | 組合せ爆発 | 構造 | 空間が広すぎて有望な組合せが未踏 | 設計空間と既踏点の桁差が3桁以上 |
| F | 動機の盲点 | 動機 | 探索する誘因を持つ主体がいない | 学会が無い、論文にならない、受益者に購買力が無い |
| G | 観測の欠如 | 認知 | 現象が計測できず、需要も案も立たない | 「経験と勘」「熟練者にしか分からない」 |
| H | 満足化の影 | 動機 | 「十分よい」既存解が探索を止めている | 現行性能と理論限界の比が2桁以上、かつ誰も比較していない |
| X | 残余 | — | A〜Hで説明不能。棄却せず隔離保持 | 敵対的検証4cで説明が立たない候補 |

## 主類型の判別(迷ったら)

```
案は着想可能か?
├─ いいえ ─ 前提が遮る→A / 計測されず見えない→G
└─ はい ─ 部品は揃っているか?
    ├─ いいえ(試されて手段不足で死んだ)→D
    └─ はい ─ 誰もその方向を見ない→B / 広すぎる→E /
              需要が無名→C / 誘因が無い→F / 「十分」が止める→H
```

判別規則の要点:
- **A vs F**: 案が思い浮かばないならA、思い浮かぶが誰も着手しないならF
- **B vs E**: 方向の問題(誰も見ていない)ならB、容量の問題(広すぎる)ならE
- **F vs H**: 誘因が誰にも無いならF、誘因はあるが「現状で十分」が止めるならH
- 複数発火は正常。主類型は「解消されたら発見が最も早まるもの」で1つ選び、残りは副類型
