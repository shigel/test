# 発明候補カード スキーマ(実行時参照用)

カードは mizai 走査の最終成果物であり、1候補=1ファイル(`05-cards/` 配下)。
全フィールド必須。埋められないフィールドがあるカードは出力しない(「不明」と書くことは許すが、フィールドの省略は許さない)。
必須フィールドの後に走査固有の追加フィールド(例: 「制約適合メモ」)を足すことは許す——削るのは禁止、足すのは自由。

## スキーマ

```markdown
# 発明候補カード <ID>: <仮称>

- **仮称**: 候補の呼び名(検索性より記憶性を優先)
- **一行仕様**: 「〜(受益者)のために、〜(対象)を、〜する方法・装置・記法」
- **未在診断**: 主類型1つ+副類型(任意)。「なぜ今まで無かったか」を3文以内で
- **イネーブラ**: 何が変わって今は可能になったのか(出典URL必須。無ければ「イネーブラ不要(常に可能だった)」と明記し、その場合は未在診断でF/C/Hのいずれかを主類型にすること)
- **部品表**: 構成要素の箇条書き。各要素に[実在確認済み(URL)|仮定]のラベル
- **価値仮説**: 受益者/苦痛/改善の桁(「誰の・どの苦痛が・何桁改善するか」)
- **フェルミ検算**: エネルギー・コスト・市場規模のうち関係する桁計算を1〜3行、計算の実物を書く
- **新規性ログ**: 実行した検索クエリの全列挙/最接近先行例とその差分/判定=[暫定新規|差分新規|既存]
- **死亡条件**: この案を最速で殺す反証は何か(1〜2件)
- **最小実験**: 48時間・低予算で実行可能な検証手順(現象の性質上不可能な場合は最小統計単位で設計し[要N日]を明記)
- **先行指標**: これが起きたら再評価すべき事象のウォッチリスト(2〜4件)
- **確信度**: [低|中|高|不明(残余X)] + 根拠1文
- **メタ**: 走査日/フレームワーク版(taxonomy 1.0等)/走査モード
```

## 記入規則

1. **新規性ログの判定語彙**(docs/03 §6): 「暫定新規」= n件の検索で反例なし。「差分新規」= 近い先行例があるが明確な差分がある(差分を明記)。「既存」= 先行例と実質同一(この場合カード化せず棄却ログへ)。「新規と証明された」とは決して書かない
2. **検索クエリの省略禁止**。新規性ログはクエリ全列挙が本体であり、判定は要約にすぎない
3. **仮定ラベルの部品が2つ以上**あるカードは確信度「高」を付けられない
4. **未在診断とイネーブラの整合**: D類型を主類型にするなら、死因と解消イネーブラの対が書けていなければならない

## 記入済みサンプル(歴史事例の遡及カード)

実在した発明を「発明前夜」の視点で遡及記入した参考例。品質の基準として使う。

```markdown
# 発明候補カード SAMPLE-01: 車輪付き旅行鞄

- **仮称**: 車輪付き旅行鞄
- **一行仕様**: 徒歩移動する旅行者のために、旅行鞄を、持ち上げずに転がして運べるようにする装置
- **未在診断**: 主類型C(名前なき需要)、副類型A(「鞄は手で提げるもの」という慣習前提)。
  鞄を運ぶ苦痛は遍在しすぎて誰の問題リストにも載らず、ポーターという人的ワークアラウンドが需要を不可視化していた。
- **イネーブラ**: イネーブラ不要(常に可能だった)。車輪は数千年前から実在。主類型が手段(D)でないことと整合
- **部品表**: 旅行鞄[実在確認済み]/小径キャスター[実在確認済み]/固定金具[実在確認済み]
- **価値仮説**: 全旅行者/搬送の身体負担/駅・空港での運搬労力を1桁削減
- **フェルミ検算**: 鞄20kg を 500m 運ぶ仕事 ≈ 持ち上げ保持の等尺性負荷 → 転がし摩擦(μ≈0.05)なら牽引力 ≈ 10N。体感負荷はおよそ1桁減
- **新規性ログ**: (遡及例のため省略。実運用ではクエリ全列挙)
- **死亡条件**: 石畳・階段が支配的な移動環境では車輪が機能しない(→ 死ななかった: 空港・駅の平滑床面の普及がD類型的な環境イネーブラとして効いた)
- **最小実験**: 手持ちの鞄にキャスターを仮止めし、駅構内500mで所要時間と主観負荷を比較する
- **先行指標**: 空港旅客数の増加/床面の平滑化/ポーター人件費の上昇
- **確信度**: 高(需要の遍在と部品の実在が確認済み)
- **メタ**: 遡及記入サンプル/taxonomy 1.0/デモ用
```
